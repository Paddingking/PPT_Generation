# 技术实现补充说明（工程侧）

> 对应 PRD 文档 `docs/PPT生成工具-PRD.md`。本文件面向**工程评审**，给出可落地的选型版本、依赖清单与易错点。所有建议满足 **JDK 1.8** 约束。

---

## 1. 版本选型（jdk8 约束下的关键依赖）

| 组件 | 建议版本 | 理由 / 注意 |
|------|----------|-------------|
| Java | **1.8** | 硬约束 |
| Spring Boot | **2.7.x**（如 2.7.18） | 官方支持 jdk8 的**最后一个主流分支**；3.x 起最低要求 Java 17 |
| Apache POI | **poi-ooxml 5.2.5** | 5.x 兼容 jdk8；**不要用 5.3+ 及 POI 6.x**（部分要求 jdk11+） |
| sqlite-jdbc | **3.44.1.0** | 兼容 jdk8 |
| Jackson | 随 Spring Boot 2.7 自带 2.13.x | 处理 JSON 大纲 |
| 构建 | Maven 3.8.x | 稳定 |

> ⚠️ 三个易踩的坑：
> 1. **Spring Boot 3.x / POI 6.x** 都要求 JDK 17，直接排除，不要误装。
> 2. POI 5.2.5 会传递依赖 `xmlbeans`、`log4j-api`，注意版本一致，避免冲突。
> 3. sqlite-jdbc 的 native 库由系统 `java.library.path` 加载，打包时确保 `jar` 内含对应平台驱动。

## 3. LLM Provider 实现要点

### 3.1 接口（PRD 5.5 已定义）

```java
public interface LlmProvider {
    CompletableFuture<String> chat(ChatRequest req);
    boolean testConnection();
}
```

### 3.2 OpenAI 兼容请求体（POST `{baseUrl}/v1/chat/completions`）

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "你是一个演示文稿大纲助手，只输出 JSON..."},
    {"role": "user", "content": "帮我做关于AI转型的PPT"}
  ],
  "temperature": 0.7,
  "response_format": {"type": "json_object"}
}
```

### 3.3 Anthropic 兼容请求体（POST `{baseUrl}/v1/messages`）

```json
{
  "model": "claude-3-5-sonnet",
  "max_tokens": 4096,
  "system": "你是一个演示文稿大纲助手，只输出 JSON...",
  "messages": [
    {"role": "user", "content": "帮我做关于AI转型的PPT"}
  ]
}
```

> **差异抽象思路**：两种协议 header 不同（OpenAI 用 `Authorization: Bearer`，Anthropic 用 `x-api-key` + `anthropic-version`），且响应字段名不同（`choices[0].message.content` vs `content[0].text`）。在 Provider 内部做解析，**上层只收统一的 String**，这样 `OutlineEngine` 无需关心协议差异。

### 3.4 HttpClient 选型

推荐 **JDK 原生 `HttpURLConnection`** 或引入 `okhttp3`（兼容 jdk8）。不推荐引入各厂商官方 SDK（多数新版本要求 jdk11+ 或有较重依赖）。

```java
// 以 okhttp3 为例（3.14.x 兼容 jdk8）
OkHttpClient client = new OkHttpClient.Builder()
        .connectTimeout(15, TimeUnit.SECONDS)
        .readTimeout(120, TimeUnit.SECONDS)   // LLM 生成慢，读超时给足
        .build();
```

## 4. Apache POI 生成 PPTX 核心片段

### 4.1 骨架

```java
XMLSlideShow ppt = new XMLSlideShow();
ppt.setPageSize(new Dimension(960, 540)); // 16:9；4:3 用 720x540

XSLFSlideMaster master = ppt.getSlideMasters().get(0);
// 获取标题占位符 / 内容占位符，按 layout 选择
for (Section s : outline.getSlides()) {
    XSLFSlide slide = ppt.createSlide();
    addTitle(slide, s.getTitle());
    addBullets(slide, s.getBullets());
}
```

### 4.2 中文处理（关键！防乱码）

```java
XSLFTextRun run = textParagraph.addNewTextRun();
run.setText(content);
// 显式设置中文字体，避免 PPT 打开后变方块
run.setFontFamily("微软雅黑");
// 汉字子集设置（配合东亚字体）
```

> 若目标机器无"微软雅黑"，可回退到"宋体"，需在主题里配置字体 fallback 列表。

### 4.3 边界保护

- `bullets` 超过 5 条时截断并打日志；内容过长时缩小字号或截断，防止单页溢出破版。
- 空标题 / 空内容页：给占位文案并跳过绘制，不抛异常。

### 4.4 逐 shape 落盘（保证"导出可编辑"）

> 核心诉求：**导出后每个文本框/形状在 PowerPoint 里都能继续编辑**。这要求在 POI 里用原生 shape 而非贴图。

```java
// ✅ 推荐：用原生文本形状，可编辑
XSLFTextBox box = slide.createTextBox();
box.setAnchor(new Rectangle2D.Double(x, y, w, h));   // 由设计决策 JSON 给出
XSLFTextParagraph para = box.addNewTextParagraph();
XSLFTextRun run = para.addNewTextRun();
run.setText(title);
run.setFontFamily(style.getTitleFont());
run.setFontSize(style.getTitleSizePt());
run.setFontColor(style.getTitleText());
box.setFillColor(style.getBackground());

// ❌ 避免：把整页渲染成图片再贴入（会变成不可编辑对象，违背需求）
// slide.createPicture(...)  仅用于确实需要图片的场景
```

> **易错点**："可编辑"的敌人是把版式做成位图。样式用 `XSLFTextBox`/`XSLFTextShape` + 字体颜色/字号属性表达，而不是导出图片。

## 5. 模板骨架提取（TemplateExtractor）

> 对应 PRD 5.6。从外部 .pptx 提取版式骨架，复用其占位符位置、主题色、字体。

### 5.1 提取流程（POI 读取 XMLSlideShow）

```java
XMLSlideShow src = new XMLSlideShow(new FileInputStream(templatePath));
Dimension size = src.getPageSize();               // 宽高比
// 1) 遍历每页，识别标题/正文占位符
for (XSLFSlide slide : src.getSlides()) {
    for (XSLFShape shape : slide.getShapes()) {
        if (shape instanceof XSLFTextShape) {
            Rectangle2D anchor = ((XSLFTextShape) shape).getAnchor();
            // 归一化为相对坐标 (0~1)，记录类型/位置/尺寸
            placeholders.add(normalize(anchor, size));
        }
    }
}
// 2) 读取主题色/字体
XSLFTheme theme = slide.getTheme();
theme.getXMLObject().getThemeElements();  // clrScheme / fontScheme
// 3) 汇总多页结构 -> 归并为 layoutGroups
```

### 5.2 易错点

| 坑 | 对策 |
|----|------|
| 页面尺寸未知时相对坐标失效 | 先 `getPageSize()` 再归一化 |
| 部分模板用母版(master)而非逐页定义版式 | 补充读 `getSlideMasters()` 的地方 |
| 背景是一整张图(无文本占位符) | `recognized=false`，回退内置模板 |
| 表格/图表/SmartArt 形状 | v1 忽略这些，仅处理文本占位符 |

## 6. 双通道 LLM 优化（Content / Style Engine）

> 对应 PRD 5.8。内容与格式**分离**成两道独立 LLM 调用，降低单次 prompt 复杂度、便于分别调试。

### 6.1 通道 ① 内容润色（ContentEngine）

- **目标**：保留本意，提升精炼度与专业性；默认**只润色不增删要点条数**（开放问题 #8 的默认取向）。
- **Prompt 要点**：给系统角色"精炼的外联文案编辑"，给用户原文 + 要求"保持结构，润色措辞，输出与输入同等条数的 JSON"。
- 输出：内容 JSON（结构同大纲 schema）。

### 6.2 通道 ② 设计决策（StyleEngine）

- **输入**：模板骨架 + 内容 JSON + 比例约束。
- **目标**：产出结构化"设计决策 JSON"（PRD 5.5），**不是**让 LLM 直接描述"加个蓝色标题"这种自由文本。
- **Prompt 要点**：给出合法取值域（坐标 0~1、字号 12~40pt、颜色 hex），要求输出严格 JSON。
- **校验**：解析后做范围检查，非法值回退骨架默认。

### 6.3 调用编排（串行依赖）

```
[内容通道跑通] → 得到内容 JSON → [样式通道输入含内容做自适应] → 得到决策 JSON
```

> 顺序有依赖：样式通道需要"内容 JSON"来判断文字量（决定字号/是否换布局），所以**不能并行**，必须内容先、样式后。

## 7. 对话式多轮优化（两阶段贯穿 · 工程实现）

> 对应 PRD 5.9。对话优化**贯穿两个阶段**：
> - **阶段A（生成前约束）**：用户输入意图后先对话设定风格/页数/要点密度，LLM 带约束产出**首版完整 JSON**（首次生成无 diff）。
> - **阶段B（预览微调，常驻主战场）**：在预览界面按指令**增量 diff** 修改内容/格式，实时刷新。
>
> 两块交互复杂度最高的核心相同：**意图路由、增量 diff、上下文、一致性、快照撤销**。

### 7.0 阶段区分：首版完整 JSON vs 增量 diff

- **阶段A**：无既有 JSON，对话结果 = **带约束的完整 内容/样式 JSON**（首次生成）。走常规内容/格式通道建立。
- **阶段B**：有既有 JSON，对话结果 = **最小 diff** 合并进现有 JSON。
- 同一套 `conversation_id` 贯穿两阶段；`conversations.stage` 字段标记当前所处阶段。

### 7.1 意图路由（改内容 or 改格式）

每轮用户指令先做一次分类，决定走内容优化还是格式优化通道：

```java
public enum Intent { CONTENT, STYLE, GLOBAL_STYLE, OTHER }

// 简易启发式 + LLM 兜底：关键词命中优先，命中不了交 LLM 判定
Intent classify(String text) {
    if (containsAny(text, "颜色","配色","字体","字号","布局","对齐","间距","主题","风格")) {
        return text.containsAny("全文","整体","统一") ? GLOBAL_STYLE : STYLE;
    }
    if (containsAny(text, "标题","要点","内容","备注","措辞","文","删","加一")) {
        return CONTENT;
    }
    return llmClassify(text);   // LLM 兜底
}
```

### 7.2 增量 diff 机制（核心·防越界）

> **铁律**：对话优化必须以**最小 diff 合并**，绝不让 LLM 重发整份 JSON（否则丢失已有定制、且易越界）。

```java
public class Patch {
    String targetPage;    // "3" 或空(全局样式才允许)
    String path;          // JSON Pointer: "slides[2].title" / "palette.primary"
    String op;            // replace | add | remove
    Object value;         // 新值
}

public class PatchValidator {
    boolean validate(Patch p, JsonNode currentJson, boolean allowGlobal) {
        // 1) 越界校验：path 指向的节点必须存在（remove）或可创建（add）
        // 2) 范围校验：value 必须落在合法域（坐标0~1/字号12~40/合法hex色）
        // 3) 越界保护：除非 allowGlobal（明确全局指令）且操作的是样式全局字段，
        //    否则 targetPage 必须匹配，不能改到别的页
        return isValid;
    }
}
```

**合并流程：**
```
用户指令 + 当前聚焦页/元素
   → 路由(intent)
   → [阶段A] LLM 产出"带约束完整 JSON" ；[阶段B] LLM 产出 List<Patch>
   → PatchValidator 逐条校验
        → 通过 → 合并进 current 内容/样式 JSON → 保存快照(见7.4) → 推送前端重绘
        → 非法   → 丢弃该条 + 返回可读提示 → 其余合法条照常应用
```

### 7.3 局部 vs. 全局一致性规则（避免"跳色"破整体）

> 用户说"改第3页标题深蓝"，默认只改第 3 页（越界保护）；但全文其他页标题不变会视觉跳色。用开关兜底。

```java
public class StyleConsistencyPolicy {
    boolean syncLocalToGlobal;   // 5.9.4 开关，默认 false(仅改该页)
    int threshold = 2;           // 同类样式被连续改 ≥2 次 → 触发"是否全局?"询问
}

// 决策逻辑
Decision decide(Intent intent, String targetPage, int sameStyleHits) {
    if (intent == GLOBAL_STYLE) return Decision.GLOBAL;
    if (intent == STYLE && syncLocalToGlobal) return Decision.GLOBAL;
    if (intent == STYLE && sameStyleHits >= threshold) return Decision.ASK_USER; // 询问确认
    return Decision.LOCAL_ONLY;   // 默认：只改该页
}
```

- `syncLocalToGlobal` 为 true 时，单页样式改动会同步为全局默认，其余页套用。
- `ASK_USER`：前端弹一次"是否应用到所有页？"，用户确认才全局。
- `LOCAL_ONLY`：严格越界保护，绝不动未指代页。

### 7.4 上下文管理（多轮记忆）

- 用 `conversation_id` 关联整个项目；每次请求携带 `history + 当前聚焦状态 + 新指令`。
- **聚焦注入**：前端把"当前选中第几页/哪个元素"一并上传，让 LLM 理解"这页""这个标题"。
- **历史摘要**：超过阈值轮数后，对早期 user/assistant 对话做摘要压缩（如保留最近 8 轮原文 + 之前的摘要），控制 token。
- **阶段A 约束传递**：阶段A对话产出的约束，作为内容/格式通道的额外 `userConstraints` 入参，随首版生成一起消费。

### 7.5 撤销/回退（快照列表·近5档）

- 每步合并前对 content/style JSON 做**快照**，写入 `snapshots` 表（kind + seq）。
- **保留最近 5 个快照**做快速回退列表；**第 6 个及更早丢弃**（控制存储与 UI）。
- 保留**回到初始生成态**一键操作（丢弃全部对话修改）。
- 前端维护 `undoStack`（近 5 个快照），点某快照即切回重绘；前端不再支持任意步跳转。

### 7.6 前端对话面板（阶段B 常驻）

- 预览界面右侧挂对话抽屉：消息列表 + 输入框（**预览后仍常驻保留**，导出前随时可继续微调）。
- 发送后局部 spinner（仅对话区，不阻塞整页），返回后按新 doc JSON 重绘对应页。
- 支持点击预览里某页设为"当前聚焦"，使指代更精准（P1）。
- 一致性询问（`ASK_USER`）在对话区内联，不打断整页操作。
- 工具提示"只改你指定的部分"缓解越界顾虑。
- **阶段A** 的对话入口在输入页面：先聊约束再生成，用户可跳过（默认允许直接生成）。

## 8. 前端预览方案

> 预览渲染从原来"只按内容 JSON"升级为"内容 JSON + 样式 JSON"联合渲染。

预览本质是**把内容 JSON + 设计决策 JSON 联合渲染成迷你幻灯片**，方案二选一：

| 方案 | 优 | 劣 | 建议 |
|------|----|----|------|
| 内置 canvas 自绘 | 轻量、可控、无依赖、易按决策JSON渲染 | 版式还原精度有限 | ✅ 首选（MVP 足矣） |
| `@eastdesire/jsb-pptx-preview` 等库 | 还原度高 | 依赖较重、风格固定、不易注入决策JSON | 若需精细还原再用 |

**要点**：
- 渲染时读取 `styles.meta.aspectRatio` + `styles.palette/typography/layoutRules`，与生成终稿保持一致——保证"预览所见即所得"。
- 每张缩略图挂在 `<canvas>` 上，就地编辑用表单浮层（改 title / bullets / 顺序 / 配色），改完重绘该页即可。
- 模板应用发生在"新建项目时"：用户上传 .pptx 或选内置 → 生成 TemplateSkeleton → 后续样式通道基于该骨架产出决策。
- 对话框收到的"最终 doc JSON"是"初始产物 + 多轮 diff 合并"后的结果，作为 POI 导出依据。

## 10. 工程自测清单（接入 LLM + 模板 + 对话前）

2. [ ] SQLite 建表成功，项目/大纲/样式/模板/配置/对话可增删改查。
3. [ ] 用一个 mock provider（先不真调 LLM）跑通"输入→内容JSON→样式JSON→预览→导出"全链路。
4. [ ] **用 2~3 个真实 .pptx 做模板提取冒烟测试**，确认能识别占位符/主题色/字体，失败模板能回退内置。
5. [ ] 中文标题/要点的 .pptx 生成后无乱码，**且在 PowerPoint 里每个文本框仍可编辑**。
6. [ ] 生成文件在 PowerPoint 与 WPS 中均可打开。
7. [ ] 再接入真实 LLM（OpenAI 兼容 / Anthropic 兼容各测一次），切换 baseUrl 免改码。
8. [ ] 样式决策 JSON 非法值（越界坐标/负字号）能回退默认，不抛异常。
9. [ ] **对话 diff 单测**：意图路由（内容/格式/全局）、patch 越界拒绝、value 非法回退、快照撤销正确。

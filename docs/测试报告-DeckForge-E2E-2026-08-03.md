## 六、导出 PPTX 可编辑性深度验证（核心卖点）

对导出文件解码 `ppt/slides/slide*.xml` 逐 shape 分析：

| slide | 图片(`p:pic`) | 原生文本 run(`<a:t>`) | 结论 |
|-------|:---:|:---:|------|
| 1 封面 | 0 | 3 | ✅ 可编辑 |
| 2 议程 | 0 | 8 | ✅ 可编辑 |
| 3~6 主体 | 0 | 5×4 | ✅ 可编辑 |
| 7 结尾 | 0 | 3 | ✅ 可编辑 |

- **图片数 = 0**：全部内容为文本框（`<p:sp>` + `<p:txBody>`）
- **命名空间**：`p:`(presentationml) + `a:`(drawingml) 标准结构
- **中文**：文本 run 内中文正常（「今日议程」「现状与挑战」等，无乱码）
- **画布**：960×540（16:9）

> ⚠️ 说明：`a:txBody` 的「a:」前缀在我的文本匹配脚本中不准确，实际元素为 **`p:txBody`**（presentationml 命名空间）。这是校验脚本的技术细节，**不影响应用正确性**——每页文本均原生可编辑，PowerPoint / WPS 可直接修改，完全符合 PRD 的「非图片」承诺。

## 十、结论与建议

**结论**：DeckForge「PPT 工作台」主链路在 Mock Provider 下**稳定可用、命名规范、导出真实可编辑**，达到演示与内测水准。14/14 E2E + 6/6 API 探针 + PPTX 深度校验全部通过。

**发版建议**：
1. **建议发版**（mock 链路无阻断项）；
2. 接入真实 LLM 前，用「约束页数」「越界指令」「多档快照」三组用例重点回归一遍——Mock 与真实 Provider 在 **页数约束**（P2-1）上可能存在实现差异，这是接入前需复核的**最高风险点**；
3. 建议将本套 E2E 纳入 CI 做发版门禁。
